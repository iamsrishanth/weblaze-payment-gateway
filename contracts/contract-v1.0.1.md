# Weblaze Observer Contract v1.0.1

This is a backward-compatible patch to the immutable `contract-v1.0.0` release. The contract-version request header stays `1`, all existing routes and schemas stay compatible, and the pair response/API version remains `1.0.0`. See `observer-v1.md` for the complete protocol and route details.

The patch adds signed `GET /api/v1/receiver-profiles`, requiring the existing `observations` grant. It requires an empty request body, rejects non-null bodies before authentication (413 above 32 KiB, otherwise 400), and allows 120 requests per device per minute. It returns only active profiles assigned to the authenticated device with a verified receiving account whose VPA matches that gateway's configured payee. Each profile exposes its UUID, source, verified non-sensitive operator label, nullable last-four hint, and exact approved SMS template ID. Labels are normalized and collapsed to whitespace, then limited to short Unicode letters, marks, spaces, and ordinary punctuation; other values become `Verified receiving account`. New profile template IDs use a restricted key format of 1–64 characters, begin with a letter, allow only letters/digits/period/underscore/colon/hyphen, and contain at most three digits total. Unsafe legacy profile IDs are omitted from discovery, while existing v1 observations continue matching their stored profile ID by exact equality. Operators must not put personal identifiers in this field; format checks cannot recognize every encoded or letter-based identifier. Operators may store only a four-digit account suffix; the gateway rejects and never stores a full account number. The endpoint never exposes a full VPA, account number, device ID, or verification evidence. The response is not cacheable.

Older gateways may return `404` for this optional endpoint. Android clients must treat that status as discovery unavailable, ignore the response body, and continue their existing observer flow. The synthetic success and legacy-server fixtures are in `fixtures/v1.0.1/`.
